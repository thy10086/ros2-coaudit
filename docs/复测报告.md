## 2. E1 旧任务恢复通信回归

从仓储、巡检、搜救三个合成配置模板，各构造 20 类有指定预期的配置变更。每个 bundle 提供原始 SROS2 格式的 before/after XML、部署映射和两个已接纳任务，合计 60 份配置变更、120 个逐任务判断。三个模板复用变更机制，属于重复可控检验。各案例的预期状态写在脚本中，另用独立 XML 解析与集合规则重新计算每个服务角色和允许路径。

阳性样例覆盖客户端和服务端分别失去取消、结果权限，XML 不变但节点改绑为缺权的 enclave，以及唯一获批回退权限丢失。阴性样例覆盖移除无关权限、策略格式变化、已有缺陷、恢复旧缺陷、同权限的身份重绑。未知样例覆盖回退审批缺失或前态不确定。

|方法|逐任务一致|检出新增退化|在 87 个无退化任务中误阻|在 6 个未知任务中输出确定|未检查任务|
|---|---:|---:|---:|---:|---:|
|ROS2-CoAudit|120/120|27/27|0|0|0|
|独立精确规则，使用同一契约|120/120|27/27|0|0|0|
|端点角色移除告警|108/120|27/27|6|6|0|
|只查更新后仍可接受新任务的消融|108/120|21/27|0|0|12|

端点角色移除告警使用解析后的节点绑定，对取消、结果或回退角色丢失直接告警。它的 6 个误阻来自主路径减少但批准回退仍有效。新准入消融的 6 个漏检是未进入检查范围，其中包括新准入关闭或改绑后失去准入能力的旧任务。27 个确认退化中，逐任务结论与独立精确规则相同。现有结果支持任务语义相对两种简化基线的增益，同契约精确规则与候选准确率持平。

## 3. E2 前后关联与有限路径精度

每个版本两个世界、两个旧任务。每个世界的覆盖集合共有四种取值，每种证据模式穷举 256 个前后矩阵。真实配对由实验声明，独立真值用合法配对上的集合差计算。

|绑定依据|笛卡尔积 UNKNOWN|关联 UNKNOWN|两方法错误确定数|候选与同关系的精确枚举不一致|
|---|---:|---:|---:|---:|
|有效|172/256|126/256|0 / 0|0|
|缺失|172/256|172/256|0 / 0|0|
|前后摘要不同|172/256|172/256|0 / 0|0|

有效关联使 46 项 UNKNOWN 转为正确结论，包含 32 个 PASS 与 14 个 FAIL。正确确定率从 32.81% 升至 50.78%，提高 17.97 个百分点。PASS 对应无新增恢复通信退化。三种证据模式复用同一批任务矩阵，结果不作独立样本显著性推断。

另用四张带未赋值布尔条件的图与精确补全对照。互斥条件控制两条串联边时，精确结果为 FAIL，v1.0.0 为 UNKNOWN。两个互补条件分别提供可行路径时，按精确判定器预先约定的布尔域，结果为 PASS，候选仍为 UNKNOWN。无条件路径与真正条件性路径的两例与精确结果一致。这说明当前可能图存在保守精度上限。关系信息有效时的确定率提升不能外推为求解精度优于同约束精确判定器。

## 4. E3 日志期限、归属与边界反例

八类日志扰动，每类五个时间参数，每个参数一对对照，共 40 对、80 条。覆盖恰好截止与晚一毫秒、完整记录缺终态、目标 ID 不符、快照摘要不符、重复请求、只有取消接受、以及窗口内有终态但覆盖不完整。

|方法|与预期一致|检出确认超时/违约|确认违约却给 PASS|证据不足却给 PASS|证据不足却给 FAIL|
|---|---:|---:|---:|---:|---:|
|ROS2-CoAudit|80/80|35/35|0|0|0|
|独立规则，使用全部证据|80/80|35/35|0|0|0|
|去掉快照归属检查|70/80|35/35|0|5|5|
|去掉覆盖完整性判断|70/80|35/35|0|5|5|
|按最后一次请求计时|75/80|30/35|5|0|0|

窗内完整不等于取消事件链完整。单独用一对日志做左截断压力测试，保留其结果，不混入预设的 80 条常规日志。

|日志|首次可见请求|观测到终态|截止|v1.0.0 实际结果|
|---|---:|---:|---:|---|
|完整事件链|100 ms|1,000 ms|700 ms|TRACE FAIL，整体 BLOCK|
|窗口从 300 ms 开始，首次请求被截掉|500 ms|1,000 ms|按窗口内请求算成 1,100 ms|TRACE PASS，整体 MODEL_PASS|

两份日志对应同一底层过程，实际首次请求是 100 ms。截断视图仍声明窗口内完整，且配置哈希匹配。对整个取消事件链作裁定时应保留 UNKNOWN，直到获得首次取消起点或覆盖证明。此例表明 v1.0.0 的正向裁定依赖采集窗口覆盖完整事件链。建议下一版区分「窗内已采全」与「事件链已采全」，并用可信的起点见证或历史记录证明首次请求。修复验收应要求截断返回 UNKNOWN、全链返回 FAIL、合法按时完成仍是 PASS。当前报告记录的是未经上述修复的发布版。

## 5. E4 ROS 2 Jazzy 容器任务仿真

使用官方 ROS 基础镜像，固定摘要 sha256:00b8d47a6e6384a2834e3d01fa87ae767876543baa574f2d64a75c04ea33c698。容器以 network none 运行，内部使用 LOCALHOST、Fast DDS 和 ROS_SECURITY_STRATEGY=Enforce。SROS2 从同一源策略生成临时签名工件，读取源策略的审计器运行在 ROS 任务进程启动前。包版本及逐次输出保存在原始记录。 [ROS 官方镜像](https://hub.docker.com/_/ros) [SROS2 项目](https://github.com/ros2/sros2)

动作服务端使用已安装的 LookupTransform 消息类型承载合成任务。普通探测创建 Send Goal、Get Result 服务客户端；恢复探测在目标已接受后再创建 Cancel Goal、Get Result 客户端，并按实际 goal UUID 请求。分服务创建使普通验收与恢复探测的覆盖明确。采用单次取消的 600 ms 观测期限，从提交取消 RPC 到客户端看到终态结果计时。SROS2 配置保留节点启动需要的类型描述服务权限，策略变更只限于指定案例的能力。 [ROS 2 Action 协议](https://design.ros2.org/articles/actions.html)

|变更|实际普通任务，20 次|实际恢复，20 次|部署前通信覆盖 / 无新增退化|恢复轨迹适配器|
|---|---|---|---|---|
|所有权限完整|20 成功|20 按期观测到取消终态|PASS / PASS|20 PASS|
|移除取消客户端权限|20 成功|20 在创建取消接口时受拒|FAIL / FAIL|无终态可比|
|移除结果客户端权限|20 在创建结果接口时受拒|20 在创建结果接口时受拒，取消已接受|FAIL / FAIL|无终态可比|
|移除未使用的诊断权限|20 成功|20 按期观测到取消终态|PASS / PASS|20 PASS|
|权限完整，应用延迟终态|20 成功|20 超过 600 ms|PASS / PASS|20 FAIL|

五种场景共 200 次探测，其中 100 次普通探测、100 次恢复探测。普通验收发现 40 次恢复通信故障中的 20 次，遗漏全部 20 次取消权限故障。完整运行回归覆盖了这两个权限故障配置。部署前审计也识别了这两个配置，并保留移除无关权限的覆盖 PASS。两类运行任务共用同一受控场景，以上比例描述本批次，不能当作独立项目的精度估计。

权限完整基线的恢复观察中位数为 258.5 ms，延迟场景为 1,207.8 ms。静态覆盖对延迟场景仍通过，采集到终态的恢复轨迹进入 TRACE 适配器后全部判为超时，两个结论对应不同性质。没有把客户端缺结果当成已知的服务器终态。

对两种权限缺失场景补跑各两次普通、两次恢复探测，单独留存 Fast DDS 的诊断输出。取消缺权卡在 cancel_goal 回复端点，结果缺权卡在 get_result 回复端点，Fast DDS 明确记录没有匹配的允许规则。这八次探测独立留档，不计入上面的 200 次。

本批次验证的是相同任务模板在不同版本独立会话中的可重复差异。实验使用分服务客户端和独立容器，会话间没有迁移真实旧 goal，也没有运行 Gazebo、测量运动或进行多 RMW 对比。研究外推应扩展到更多运行场景，单独设计正式目标迁移证据。

## 6. E5 证据定位与使用成本

自动核对了 E1 的 27 个新增退化。33 个应被拒绝的解释项全部关联到正确的更新后 XML enclave 行，27 个案例的相关拒绝角色均能定位。此为文件、行号及身份的可追溯性核对。工程师是否能更快排查仍需要人工对照，当前没有人工完成时长、主观评分或人因优势结论。
