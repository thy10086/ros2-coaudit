# ROS2-CoAudit 批量权限变更对照实验

2026 年 11 月 20 日 · 复跑 ROS2-CoAudit v1.0.0，基于原发布 ZIP 干净解压。发布包 SHA-256：`a462e702ddae502272e165e09be4228fc8e67414d028a76f45f471998af874a6`。

**结论：在同一次发布增删 500 项授权时，只看策略差分或只查普通通信，均未发现 3 个因身份换绑产生的取消退化；ROS2-CoAudit 报告了 3 个。用同一份更新后 XML 做了容器对照，其中一个代表任务普通探测 20/20 成功、恢复探测 20/20 在创建取消接口时受拒。**

## 实验比较了什么

每份发布包有 12 个已接纳任务，策略内同时增删 100、500 或 2,000 项诊断服务授权。500 项就是增加 250 项、删除 250 项。再设置四种受控变更：[实验设计](实验设计.md)。

| 情形 | 更新后发生什么 | 每档预设退化 | 旧绑定权限差分检出 | 普通通信检查检出 | ROS2-CoAudit 检出 |
|---|---|---:|---:|---:|---:|
| 等权换绑 | 3 个任务节点改绑到权限相同的身份 | 0 | 0 | 0 | 0 |
| 缺权换绑 | 3 个任务节点改绑到缺少取消授权的身份 | 3 | 0 | 0 | 3 |
| 直接删权 | 另外 3 个任务的取消客户端授权直接删除；绑定不变 | 3 | 3 | 0 | 3 |
| 混合 | 同时做缺权换绑和直接删权 | 6 | 3 | 0 | 6 |

直接删权和混合组在诊断授权变更之外各再删除 3 条取消授权，所以该两组实际增删分别是 103、503、2,003 项。数量基于解析 XML 后的授权集合差，不是代码行数。等权换绑与缺权换绑每档前后两份策略的字节内容都分别相同；直接删权与混合在每档也一样。仅凭 XML 无法区分这些配对，而直接删权组证明对照 A 确实会报告它看得到的取消授权变化。

| 方法 | 使用的信息 | 判定一致 | 检出退化 / 阳性 | 漏报 | 误报 / 阴性 |
|---|---|---:|---:|---:|---:|
| A：旧绑定权限差分 | 两份 XML、旧节点绑定、恢复接口 | 126/144 | 18/36 | 18 | 0/108 |
| B：普通通信检查 | 更新后的实际绑定，只查下发任务和读取结果两侧权限 | 108/144 | 0/36 | 36 | 0/108 |
| ROS2-CoAudit | 前后绑定、前后策略、任务契约 | 144/144 | 36/36 | 0 | 0/108 |
| 独立精确参照 | 同样的前后绑定及契约，独立解析 XML 和匹配集合 | 144/144 | 36/36 | 0 | 0/108 |

三个规模各复用四种变更、12 个任务，共 144 个任务判断，含 36 个新增退化、108 个无新增退化。没有未知的逐任务回归标签。表中的统计只针对「是否新增通信退化」：变更包未提供运行日志，所以正常的等权组总门禁是 `REVIEW`，不是 `MODEL_PASS`。换绑的迁移前提也会单独标 `UNKNOWN`，不阻止工具指出已经确定的通信退化。

## 一个可以复核的 500 项样例

两包使用相同策略：`/operator` 有取消权限；`/equivalent_1` 和它等权；`/restricted_1` 有 `send_goal` 和 `get_result`，没有 `cancel_goal` 的客户端授权。三个 enclave 在旧策略里已经存在。该样例从旧绑定 `/operator` 切换到 `/restricted_1`：

```text
旧绑定权限差分：仍用 /operator 解释两份策略 → 取消权限没被删 → 不报
普通通信检查：  用新身份查 send_goal 和 get_result → 两项齐全 → 不报
ROS2-CoAudit： 新身份 /restricted_1 缺 cancel_goal 的客户端角色 → 新增退化
```

`task_01:cancel:request:operator` 的结果是 `DEFAULT_DENY`，定位到 [after.xml 第 591 行所在的 enclave](run/inputs/500_restricted/after.xml)。这里定位的是应核对的策略块；规则缺失本身没有一条可指的 XML 行。[更新前绑定](run/inputs/500_restricted/before.json) · [更新后绑定](run/inputs/500_restricted/after.json) · [完整审计输出](run/inputs/500_restricted/result.json)

## 用实际中间件核对

复用之前的无运动 Action 服务端和客户端探测，Docker `--network none`、ROS 2 Jazzy、Fast DDS、`ROS_SECURITY_STRATEGY=Enforce`。用一份更新后 XML 生成一套临时安全工件。两个客户端进程保持节点名不变，分别使用两份快照声明的 enclave。两组执行同样的任务模板，恢复探测在目标被接纳后按实际 goal ID 请求取消。仅运行静态 12 个任务中的 `task_01` 对应模板。

| 更新后绑定 | 普通探测 | 恢复探测（600 ms 阈值） |
|---|---|---|
| `/equivalent_1` | 20/20 成功 | 20/20 按时观察到 `CANCELED`；中位数 256.1 ms |
| `/restricted_1` | 20/20 成功 | 20/20 目标已接纳，但在创建取消客户端时被拒绝 |

共 80 次探测。Fast DDS 记录取消服务的回复端点没有匹配的允许规则；这是客户端创建服务通信所需端点时的拒绝。在缺权组没有观测到恢复终态，不能由此推断服务端最终状态。[原始运行记录](run/runtime_results.json)

## 耗时与结论边界

| 一次发布的无关授权增删 | 静态审计中位数 | 最大值 | 计时次数 |
|---:|---:|---:|---:|
| 100 | 14.4 ms | 27.9 ms | 20 |
| 500 | 19.5 ms | 39.3 ms | 20 |
| 2,000 | 24.9 ms | 44.5 ms | 20 |

Windows、Python 3.12.14、Intel Core Ultra 9 285H。每档对四份发布包各审计 5 次，用同一进程计时，包含读取文件、解析策略、建模和给出证据，不含容器、HTML 生成或人工复核。诊断授权增删集中在一个与任务无关的 enclave，任务数固定为 12，最大更新后 XML 约 75 KB；这些数据不能外推到同时增加大量任务、大量互相依赖的授权变动或任意规模。

差异来自**使用了更新后的身份绑定和任务恢复约束**，没有证据说明规模本身造成了漏报。完整参照使用同样的证据，与 ROS2-CoAudit 持平。两种自建基线各有明确的检查范围，不能代表所有管理员或权限工具。容器是不同绑定下的独立会话，未迁移同一个运行中的 goal、未运行物理运动。没有测人工审查耗时，也没有测试每个退化在其他中间件上的复现率。
